# Working on the Row & Reason organization profile

This public repository owns the GitHub organization profile; its instructions apply
here, not automatically to other repositories.

## Workflow

- Track every work item in Linear. Read/reuse the matching issue or create it;
  keep scope, status, blockers and project relationships current. Link PRs.
- Before creating an issue or project, list the current templates available to
  its target team, read the appropriate issue/project template, and apply it using
  Linear's tools. Do not assume template names or a fixed list. Fill prompts,
  omit unused sections, and report unavailable access/templates as a blocker.
- Issues, comments and project updates lead with the outcome/current state and
  next action/decision. Use concise paragraphs and useful headings/lists. Preserve
  decisions/reasons, results with units/denominators/conditions, and uncertainties.
  Keep one current summary; link detailed evidence. Comment only on meaningful
  changes. Put completion/replacement and successor links first.
- Inspect Git status; preserve unrelated work. Prefer small changes and supported
  upstream APIs over speculative abstractions. Consult relevant official docs and
  installed guides for the locked version; explain material deviations in Linear.
- Run focused checks, update affected docs, and report passed/failed/not-run checks
  and limitations. Local validation does not prove live deployment or authorize it.

## Scope and checks

- Keep `profile/README.md` and root README company copy/links consistent with the
  established voice. Do not publish unverified legal, customer or performance
  claims, private operational details, credentials or customer data.
- Check Markdown, paths, links and the rendered profile; there is no application
  build/test suite here.
